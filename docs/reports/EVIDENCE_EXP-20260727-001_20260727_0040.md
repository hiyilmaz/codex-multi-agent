# Evidence: EXP-20260727-001 Conditional Hypothesis Workflow

Date: 2026-07-27

## Problem

The runtime lacked the conditional experiment workflow tracked by ORCH-005.
Making every task an experiment would duplicate records and increase latency.

## Hypothesis

A short global activation gate plus a reusable skill can add traceability only
when failure, uncertainty, regression, comparison, governance risk, or an
explicit user request justifies it.

## RED Evidence

The first valid focused run reached the new contract and failed because the
skill files, global policy, registry links, and installed runtime artifacts did
not exist. The result was 7 failing assertions and 3 missing-file errors across
7 tests.

## Solution

- Added identical `hypothesis-workflow` skills and UI metadata to Codex and
  Dolphin runtime packages.
- Added concise conditional activation rules to both global runtime policies.
- Registered the skill without adding it to project `AGENTS.md`.
- Reused project `CHANGELOG_PATH` and `EVIDENCE_PATH`.
- Preserved the mandatory agent chain and `medium` reasoning defaults.
- Synchronized only the required active `~/.codex` files after archiving their
  prior versions.

## Validation

- Focused hypothesis workflow suite: 7 tests passed.
- Complete unit suite: 19 tests passed.
- Codex packaged skill validation: PASS.
- Dolphin packaged skill validation: PASS.
- Active global skill validation: PASS.
- Global and Codex AGENTS template equality: PASS.
- Codex and Dolphin temporary installation coverage: PASS.
- Active global policy, skill, and registry source equality: PASS.
- Existing active audit history preservation: PASS.
- `git diff --check`: PASS.

## Decision

ACCEPT. The workflow is available globally but remains conditional, adds no
mandatory orchestration stage, and creates no project experiment records until
a trigger exists.
